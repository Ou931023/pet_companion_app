# DEMO_SCRIPT — AI 寵物陪伴系統 正式展示腳本（CR-0074）

> 用途：成果發表 / 口試的 5–7 分鐘正式展示。照著做即可，含每步「畫面 / 講稿 / 操作 / 測試句」與備援方案。
> 性質：**docs-only**，不改任何程式。測試句已對照 `backend/companion/safety_guard.js` 的分級規則，可可靠觸發對應風險且適合公開展示。

## 2. 測試句庫（已對照 `safety_guard.js`，可靠且得體）

> 分級規則：**Telegram 只推 high / urgent；medium 只進 caregiver_web 照護提醒（不推 Telegram）**。這正是系統「分級、不疲勞轟炸」的價值，展示時要講出來。打字對話（`/api/companion/chat`）在 medium/high/urgent 都會建立 Care Alert，所以用打字觸發最穩。

| 用途 | 測試句 | 預期結果 |
|---|---|---|
| 長期記憶（建立） | 「我叫阿明，我女兒住台中，我喜歡每天去公園散步。」 | 自然回應；後台寫入長期記憶 |
| 長期記憶（回憶，**開新對話**後問） | 「你還記得我女兒住哪嗎？我平常喜歡做什麼？」 | 寵物答得出「台中 / 散步」 |
| 打字陪伴（情緒接住） | 「今天有點悶悶的，沒什麼精神。」 | 溫暖陪伴回覆 |
| **medium** Care Alert | 「我這幾天都睡不好，晚上常醒來，白天也沒什麼胃口。」 | 建立 medium（睡不好 + 沒胃口）→ **caregiver_web 照護提醒**出現；**不推** Telegram |
| **high** Care Alert（觸發 Telegram） | 「最近每天都好難過，覺得沒有人需要我。」 | 建立 high（每天都好難過 + 沒有人需要我）→ **Telegram 即時通知** + caregiver_web |
| 台語語氣 | 「今仔日有較無聊，食袂落去。」 | 自然台灣口吻回應（含 medium 食慾訊號） |

> ⚠️ urgent 級（自傷 / 跌倒 / 胸痛等）**不建議現場觸發**；用講的帶過「更嚴重會升為 urgent、立即提示」即可。

## 3. 5–7 分鐘 Demo 流程（逐步）

### Step 1 — 開場與首頁（約 0:30）
- **畫面**：iPhone App 首頁——AI 寵物、麥克風按鈕、清楚的「可以說話」狀態。
- **操作**：停在首頁，指出大字 / 大按鈕 / 寵物狀態。
- **講稿**：「這是給長輩用的 AI 陪伴寵物。介面刻意大字大按鈕，一眼知道現在能不能說話。它的核心不是聊天機器人，而是**陪伴 + 記得你 + 在你不對勁時提醒家人**。」

### Step 2 — 即時語音對話（含台語）（約 1:00）
- **操作**：點麥克風說一句中文（如「今天天氣不錯，陪我聊聊」），等寵物即時語音回覆；再說一句台語測試句。
- **畫面**：說話時「聆聽中」、回覆時寵物開口、文字泡泡同步。
- **講稿**：「走 OpenAI Realtime 即時語音，不是錄完才送；也聽得懂台語語氣，用自然的台灣口吻回。」
- **備援**：場地吵雜辨識不佳 → 改用打字（下一步本就打字），功能等價。

### Step 3 — 打字陪伴 + 長期記憶（約 1:20）
- **操作**：① 打字輸入記憶建立句「我叫阿明，我女兒住台中，我喜歡每天去公園散步。」→ 看回應。② **開一段新對話**，打字問「你還記得我女兒住哪嗎？我平常喜歡做什麼？」
- **畫面**：新對話裡寵物答得出「台中 / 散步」。
- **講稿**：「重點在這——**換一段對話，它還記得你說過的事**。背後是長期記憶：把名字、家人、喜好抽取、向量化存起來，下次自然想起來，而不是像查資料庫那樣念出來。」
- **備援**：回憶不夠精準 → 說明機制，並改在同一段對話內展示「記得剛說的事」。

### Step 4 — Care Alert 分級（medium，不推 Telegram）（約 0:50）
- **操作**：打字輸入 medium 測試句「我這幾天都睡不好，晚上常醒來，白天也沒什麼胃口。」
- **畫面**：寵物**仍以溫暖陪伴語氣**回應（前台不出現監控 / 警示字樣）。
- **講稿**：「長輩端永遠只看到陪伴，不會覺得被監視。但後台同時做風險分析——這句判為 **medium（需持續觀察）**，只進管理端、不打擾家屬。」

### Step 5 — Care Alert 分級（high → Telegram 即時通知）（約 1:00，壓軸）
- **操作**：打字輸入 high 測試句「最近每天都好難過，覺得沒有人需要我。」
- **畫面**：① App 端寵物溫暖回應；② 切到 **Telegram**，秀剛跳出的即時通知（風險摘要 + 對話片段）。
- **講稿**：「同一套陪伴，這句升為 **high**——系統判斷需要讓家屬知道，就**即時推 Telegram**。medium 不推、high/urgent 才推，避免疲勞轟炸。」
- **備援**：Telegram 延遲 → 先往下走稍後回來秀；或直接到 caregiver_web 看這筆 high 已入列佐證分級。

### Step 6 — caregiver_web 管理端（約 0:50）
- **操作**：切 caregiver_web（已登入 super_admin + Admin Token），開「照護提醒」分頁刷新。
- **畫面**：medium 與 high 兩筆都在；點開看風險等級 / 摘要 / 對話片段；可更新狀態（new → acknowledged → resolved）。
- **講稿**：「家屬 / 長照人員端看到的是**整理過的重點**——誰、什麼風險、說了什麼、處理到哪，不是一堆技術資料；狀態可追蹤。」

### Step 7 — 照護用品商城（約 0:50）
- **操作**：App 進「照護商城」→ 商品列表（15 項）→ 點商品看詳情 → 加入購物車 → 下單。再切 caregiver_web「訂單管理」看到該訂單、可改狀態 / 刪除。
- **畫面**：商品列表、詳情、下單成功（金額 / 分潤）、管理端訂單。
- **講稿**：「商城是平台自有、PostgreSQL 正式資料；下單即時扣庫存、算平台抽成與長照中心實收，管理端能管訂單。」

### Step 8 — 今日任務 + 拍照 AI 驗證（約 0:50）
- **操作**：App 進「今日任務」→ 選一項（吃藥 / 喝水 / 運動）→ 拍照完成上傳 → 看 AI 影像驗證結果。再切 caregiver_web「日常任務」看任務 + 最新完成紀錄。
- **畫面**：任務列表、拍照、AI 判斷（相符 / 需人工確認）、管理端 submission。
- **講稿**：「長輩拍照完成任務，AI 看照片判斷是否相符——文案只說『照片相符 / 需人工確認』，**不宣稱藥物劑量正確**，醫療判斷留給人。」

### Step 9 — 總結（約 0:30）
- **講稿**：「四個重點：**① 即時語音 + 台語陪伴；② 會記得你的長期記憶；③ 陪伴中默默做 Care Alert 四級分析、high 以上即時通知家屬；④ 管理端 + 商城 + 今日任務形成照護閉環**。長輩端只感受到陪伴，家屬端拿到該注意的重點。」

## 5. 全域備援方案

| 狀況 | 備援 |
|---|---|
| 場地網路不穩 | 切手機熱點；後端在雲端，App 有網路即可。 |
| 語音辨識被噪音干擾 | 改用打字示範（流程本含打字），功能等價。 |
| Telegram 通知延遲 | 先往下走稍後回頭秀；或以 caregiver_web 該筆 high 已入列佐證分級。 |
| 某句風險落點與預期不同 | 以 caregiver_web 實際顯示的等級為準，順勢說明「系統就是這樣分級」。 |
| 後端冷啟動慢（Render） | 開講前先打一次 `/health` 喚醒。 |
| 通知有冷卻（同來源同等級短時間只推一次） | high 測試句若沒推，等冷卻過或換句再試；caregiver_web 仍會有該筆。 |
| 商城 / 今日任務當下資料異常 | 先展示列表與管理端，下單 / 拍照若卡住改用講述帶過。 |

> 任何一步若真的失敗：保持鎮定，用 caregiver_web 管理端既有資料佐證功能存在，**不要當眾除錯、不要打開後台密鑰或 log**。

## 6. 評審可能提問（快答）

- **會不會讓長者覺得被監視？** 前台只看到陪伴，看不到風險等級 / 分析；風險資訊只在後台給家人 / 照護人員。
- **風險怎麼分級？** low / medium / high / urgent；只有 high / urgent 主動推 Telegram（`safety_guard.js` / `PROJECT_ARCHITECTURE.md §5`）。
- **會不會一直洗版通知？** 有冷卻機制（同來源同等級短時間內只推一次）。
- **是真串接還是假的？** Realtime 語音、OpenAI 分析與記憶 embedding、Telegram、PostgreSQL 持久化、商城下單扣庫存都是真的。
