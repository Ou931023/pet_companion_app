## 任務背景

本專案是長者 AI 寵物陪伴系統，目前已完成：

- 長者端 App
- OpenAI Realtime 語音陪伴
- Companion Analyze 情緒分析
- Care Alert 長照提醒
- Telegram 高風險通知
- caregiver_web 管理者端
- CR-0028 正式版情緒辨識與 Care Alert 分析紀錄
- CR-0029 正式版管理者端使用者帳戶管理

目前管理者端已能查看 Care Alert 與使用者帳戶資訊，但評審老師可能會問：

- 管理者端除了警示，還能看到什麼分析？
- 長者的心理健康狀態怎麼追蹤？
- 情緒變化有沒有歷史紀錄？
- 生理健康有沒有分析？
- 小遊戲的退化指標怎麼呈現？
- 這些分析資料從哪裡來？
- 這是不是醫療診斷？

本次 CR-0030 要完成「正式版管理者端健康分析儀表板」，讓管理者端不只顯示警示，而是能以正式展示方式呈現：

1. 生理健康分析
2. 心理健康分析
3. 情緒分析歷史
4. 遊戲退化指標
5. 長者個人健康摘要
6. 非醫療診斷提示

## 核心原則

1. 不准新增 fake data。
2. 不准 hardcode demo analytics。
3. 不准為了展示做假趨勢圖。
4. 優先使用現有資料來源：Care Alert、Companion Analyze、情緒結果、對話紀錄、任務紀錄、小遊戲紀錄。
5. 如果某類資料目前不足，需顯示「資料不足」狀態，而不是捏造資料。
6. 分析結果不是醫療診斷，只能作為照護輔助參考。
7. 不要破壞現有 Realtime、Care Alert、Telegram、長期記憶、情緒辨識、登入註冊、CR-0029 使用者管理。
8. 管理者端分析頁需和現有 caregiver_web UI 風格一致。
9. 後端 API 不可暴露敏感資料。
10. 若資料來源目前仍有 JSON fallback，需誠實記錄，不可宣稱全部已 PostgreSQL 化。
