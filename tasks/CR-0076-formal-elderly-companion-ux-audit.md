# CR-0076 Formal Companion Retention UX Audit and Engagement Polish Plan

## 背景

本專題目前已進入正式 Demo 前收尾階段。系統主要功能已完成：

* AI 寵物陪伴
* OpenAI Realtime 語音互動
* 台語 / 國語對話展示
* 長期記憶
* 情緒辨識
* Care Alert
* Telegram 通知
* caregiver_web 長照管理端
* 照護商城 PostgreSQL production enabled
* 今日任務 PostgreSQL production enabled
* Production backend / caregiver_web 已部署

但目前需要進一步確認：App 是否真的像一個正式的「長者陪伴 App」，而不只是功能集合。

本系統的核心價值不是單純聊天，也不是單純管理後台，而是：

1. 讓長者每天願意打開 App。
2. 讓長者願意和 AI 寵物互動。
3. 讓寵物透過記憶、任務、獎勵與狀態建立陪伴感。
4. 讓互動自然產生照護資訊，降低長照人員主動追問與巡查負擔。
5. 讓長照中心能更早掌握情緒低落、身體不適、任務未完成等狀況。

因  目標：找出 Demo 前最小可修、風險最低、最能提升正式感的問題。

## 嚴格限制

本 CR 預設只做 audit / plan，不要直接大改 code。

允許：

* 閱讀 Flutter app code
* 閱讀 caregiver_web code
* 閱讀 docs
* grep / 靜態分析
* 找問題
* 分 P0 / P1 / P2
* 提出最小修正方案
* 提出後續 CR 拆分

禁止：

* 不要改後端 API 契約
* 不要改 Realtime 主流程
* 不要改 Auth 流程
* 不要改 Marketplace / D音或文字和寵物聊天
* 寵物會記住他的名字、家人、喜好
* 完成今日任務可以讓寵物更健康 / 增加互動回饋
* 金幣可以用來解鎖寵物外觀或提升養成感
* 商城是照護用品展示 / 訂購，不是遊戲商店
* 若系統發現需要關心的狀況，會提醒照護人員

請特別檢查：

1. 新手導覽是否太像功能說明，而不是陪伴引導。
2. 導覽是否有明確告訴長者「現在可以先做什麼」。
3. 導覽結束後是否有第一個任務或第一句話引導。
4. 長者是否會不知道語音按鈕怎麼用。
5. 長者是否會不知道金幣有什麼用。
6. 長者是否會不知道今日任務做完有什麼好處。

回饋，不讓老師覺得功能做了但看不到效果。

請建議：

* 初始金幣
* 每日簽到金幣
* 完成今日任務金幣
* 聊天 / 語音互動金幣或親密度
* 寵物換皮價格
* Demo 帳號應預先擁有多少金幣

### Production-friendly 數值

目標：正式長期使用不會太快膩，也不會太難獲得。

請建議：

* 每日可獲得上限
* 任務獎勵
* 換皮價格
* 連續簽到獎勵
* 是否需要週獎勵
